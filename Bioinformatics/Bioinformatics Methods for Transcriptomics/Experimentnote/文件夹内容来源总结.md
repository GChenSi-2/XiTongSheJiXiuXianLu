# 文件夹内容来源总结

> 本笔记总结当前 vault 中除 `NGS工具测试.ipynb` 之外，相关文件大概是怎么来的、内容是什么。重点关注 `Bioinformatics/Bioinformatics Methods for Transcriptomics/` 以及整个 vault 的主要来源。

## 1. 当前转录组学文件夹

位置：`Bioinformatics/Bioinformatics Methods for Transcriptomics/`

这个文件夹主要围绕 **NGS / bulk RNA-seq 工具测试与数据分析准备**。

### 数据与环境文件

- `SraRunTable.csv`
  - 来源：NCBI / GEO / SRA 导出的 run metadata。
  - 内容：小鼠海马 RNA-seq 数据表，包含 `Run`、`AGE`、`BioProject`、`GEO_Accession`、`sex`、`tissue` 等字段。
  - 用途：用于确定要下载和分析的 SRR/GSM 样本。

- `ngs_backup.yml`
  - 来源：`ngs` conda 环境导出。
  - 内容：conda channels 和依赖包列表。
  - 用途：备份或复现 `ngs` 生信环境。

### STAR 测试残留

- `Log.out`
- `output_Log.out`
- `Aligned.out.sam`
- `output_Aligned.out.sam`
- `_STARtmp/`
- `output__STARtmp/`

这些是运行 STAR 比对测试时自动生成的文件。日志里显示使用了占位参数，例如：

```text
/path/to/genome
read1.fastq
```

因此 STAR 报错：

```text
could not open readFilesIn=read1.fastq
```

结论：这些更像是 **工具调用测试残留**，不是正式比对结果。

### ExperimentNote 下的笔记

- `CookBook.md`
  - 内容：`ngs` 环境使用小抄。
  - 主要讲 `pysradb` 查询 SRA/GEO metadata、`fastq-dl` 下载 FASTQ，以及 GSE/GSM/SRP/SRX/SRR 编号之间的关系。

- `Data Source.md`
  - 内容：RNA-seq 数据来源和分析流程总结。
  - 记录了 Trimmomatic、TopHat、SAMtools、easyRNASeq、DESeq2、Cufflinks 等 bulk RNA-seq pipeline。

### 自动生成 / 缓存 / 配置文件

以下目录大多不是手写内容，主要由 Obsidian、Jupyter、Quarto、Claudian、插件或 Git 自动生成：

- `.obsidian/`：Obsidian 配置和插件。
- `.claudian/`：Claudian / Codex / Claude 插件配置。
- `.smart-env/`：智能环境、embedding、上下文缓存。
- `.git/`：Git 版本库。
- `.ipynb_checkpoints/`：Jupyter checkpoint。
- `.virtual_documents/`：Jupyter / Obsidian 插件生成的虚拟文档。
- `.quarto/`、`_freeze/`、`_output/`：Quarto 缓存与渲染输出。
- `anaconda_projects/db/project_filebrowser.db`：Anaconda 项目浏览器数据库。

## 3. 一句话结论

除 `NGS工具测试.ipynb` 外，这个 vault 主要由以下几类内容组成：

1. 操作系统课程和实验笔记。
2. React / TypeScript / 前端工程学习笔记。
3. Jupyter、Conda、Obsidian、Quarto 的环境搭建记录。
4. NGS / RNA-seq / 生信工具测试和数据来源记录。
5. AI research 论文笔记和基因组 AI / molecular design 材料。
6. Obsidian 插件、Claudian、Jupyter、Quarto 等工具自动生成的配置和缓存。

真正值得长期保留和整理的是 `.md` 笔记、PDF、项目资料和环境复现文档；点号目录、checkpoint、STAR 占位测试日志、Quarto/Jupyter 缓存多半属于自动生成或测试残留。
