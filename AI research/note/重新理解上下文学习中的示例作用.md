# 重新理解上下文学习中的示例作用

> 原论文：*Rethinking the Role of Demonstrations: What Makes In-Context Learning Work?*  
> 本地 PDF：[[AI research/2202.12837v2.pdf]]

## 一句话总结

这篇论文发现：在很多分类和多选任务里，少样本提示（in-context learning）之所以有效，并不主要因为模型从示例中学到了“输入应该对应哪个正确标签”，而是因为示例告诉了模型 **任务格式、输入大概长什么样、可选标签有哪些**。换句话说，示例更像是在“唤醒/定位”模型已有能力，而不是在推理时真正教会模型一个全新的映射规则。

## 背景：什么是 in-context learning？

大语言模型可以在不更新参数的情况下，通过 prompt 里的几个示例来做新任务。例如：

```text
句子：这家公司利润增长了。
标签：正面

句子：这笔交易没有披露价格。
标签：中性

句子：新句子……
标签：？
```

这里前面的“句子 + 标签”就是 demonstrations（示例）。传统直觉会认为：模型是从这些示例里学习“什么输入对应什么标签”。这篇论文挑战了这个直觉。

## 作者真正想问的问题

> 示例到底给模型提供了什么有用信息？

作者把一个示例拆成四类可能有用的信息：

1. **输入-标签映射**：这个输入是否配了正确标签。
2. **输入分布**：示例里的文本是否和测试样本来自类似领域/任务。
3. **标签空间**：模型是否知道可选标签有哪些，例如 `positive / neutral / negative`。
4. **格式**：prompt 是否呈现为“输入 -> 标签”的结构。

论文的核心结论是：第 2、3、4 点往往比第 1 点更关键。

## 实验怎么做？

作者在 26 个分类和多选数据集上测试，任务包括情感分析、自然语言推理、仇恨言论检测、问答和句子补全等。

使用的模型包括：

- GPT-2 Large
- MetaICL
- GPT-J 6B
- fairseq 6.7B / 13B
- GPT-3（Davinci，论文中按 175B 处理）

默认每个 prompt 放入 `k = 16` 个示例，并比较三种情况：

| 设置 | 含义 |
|---|---|
| No demos | 不给示例，类似 zero-shot |
| Gold labels | 示例使用正确标签 |
| Random labels | 示例中的标签被随机替换 |

## 最反直觉的发现：随机标签也几乎能用

作者把示例中的正确标签随机打乱/替换后，模型表现只小幅下降：

- 分类任务平均只下降约 **2.6 个百分点**。
- 多选任务平均只下降约 **1.7 个百分点**。
- 多数模型的下降范围大约在 **0–5 个百分点**。
- MetaICL 尤其明显，随机标签相对正确标签只下降 **0.1–0.9 个百分点**。

这说明：模型并没有强依赖示例中“这个输入对应这个正确标签”的配对关系。

## 那示例到底有什么用？

### 1. 示例告诉模型输入来自什么分布

如果把示例里的输入换成完全无关的句子，即使标签空间和格式还在，性能也会明显下降。论文中部分设置下降约 **3–16 个百分点**。

直观理解：如果任务是金融情感分析，prompt 里放金融新闻句子会比放随机网页句子更容易让模型进入正确的“任务状态”。

### 2. 示例告诉模型标签空间是什么

对于直接生成标签的模型，如果把 `positive / neutral / negative` 这类真实标签换成随机英文单词，表现会明显变差，下降约 **5–16 个百分点**。

直观理解：模型需要知道答案应该从哪些词里选。标签本身携带了语义，比如 `positive` 本来就和正面情绪有关。

### 3. 示例告诉模型输出格式

如果只给一串输入、不写标签，或者只给一串标签、不写输入，效果通常接近甚至差于 zero-shot。

所以，“输入 + 标签”这种成对格式本身非常重要。它会提示模型：接下来也应该按同样结构补全答案。

## 可以把结论画成这样

```text
少样本示例为什么有效？

正确输入-标签配对      影响较小（但不是完全没用）
        │
        ▼
输入分布 + 标签空间 + 输入-标签格式
        │
        ▼
帮助模型定位任务，调用预训练中已有的能力
```

## 这篇论文对“模型是否在测试时学习”的回答

取决于怎么定义“学习”：

- **严格定义**：如果学习指“从示例中学到新的输入-标签对应关系”，那论文结果表明模型并没有真正这样学。
- **宽松定义**：如果学习指“根据 prompt 适应任务格式、输入分布和标签空间”，那模型确实从示例中获得了有用信息。

论文更倾向于说：LLM 的很多能力已经在预训练中形成，示例主要帮助模型把这些能力调出来。

## 对 prompt 设计的启发

1. **示例要像测试输入**：优先选择和目标任务同领域、同风格的输入。
2. **标签要清楚**：明确给出可选标签，最好使用语义清晰的标签词。
3. **格式要稳定**：所有示例保持一致格式，让模型知道该如何续写。
4. **有真标签当然仍然用真标签**：论文不是说标签完全没用，而是说在这些任务里，正确配对的重要性小于直觉预期。
5. **不要过度迷信 few-shot 示例数量**：论文发现当 `k` 增加到一定程度后，收益并不总是明显增加。

## 重要限制

这篇论文的结论主要来自：

- 分类任务和多选任务；
- 自然语言 benchmark；
- 具体的模型和 prompt 形式；
- macro-level 平均结果。

因此不能简单推广到所有任务。比如开放式生成、数学推理、链式思维 prompt，或者需要学习全新符号规则的任务，可能更依赖正确示例。

## 我的理解

这篇论文的重要性在于，它把“few-shot prompt 中的示例”从一种类似训练数据的东西，重新解释成一种 **任务定位器**：

- 示例给模型看“现在我们在做什么类型的任务”；
- 标签词告诉模型“答案空间在哪里”；
- 输入样本告诉模型“该关注什么分布”；
- 格式告诉模型“接下来怎么输出”。

所以，在实际使用 LLM 时，few-shot 示例不只是为了“教答案”，更是为了减少任务歧义，让模型更容易调用它已经学到的知识。

## 适合引用的核心观点

> In-context learning 的收益不一定来自模型在推理时学习了新的输入-标签映射；很多时候，示例只是通过输入分布、标签空间和格式，把模型已有的预训练能力激活出来。
